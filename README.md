# ReadQRToxlsx · 선교헌금 QR 입력

서울반석교회 선교헌금 엑셀을 연결하고 QR 스캐너의 `항목번호-ID`를 읽어 선택한 입금일에 금액을 기록하는 Python/Tkinter 데스크톱 앱입니다. 2026년 10월 4일 기준 통합문서와 같은 폴더의 JPEG를 기준으로 구조와 신규 QR을 검증했습니다.

## 실행

Python **3.10 이상**, Tkinter가 필요합니다. 이 작업 환경에는 실행 가능한 `.venv`를 구성했습니다.

```sh
.venv/bin/python main.py
```

다른 컴퓨터의 최초 설치:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python main.py
```

Windows에서는 `python -m venv .venv`, `.venv\Scripts\python -m pip install -r requirements.txt`, `.venv\Scripts\python main.py`를 사용합니다. Python 설치 시 Tcl/Tk 항목을 포함하세요. macOS의 Python에 Tk가 없다면 Tk가 포함된 Python을 사용해 가상환경을 만들어야 합니다.

실행할 때 파일을 바로 지정할 수도 있습니다:

```sh
.venv/bin/python main.py "/절대경로/선교헌금.xlsx"
```

## 입력 방법

1. **엑셀 열기**로 `.xlsx` 파일을 연결합니다.
2. **데이터 시트**, **작정 연도**, **입금일**을 선택합니다. 연도는 `YYYY년 작정금액` 머리글에서 자동으로 읽습니다. 입금일은 실제 존재하는 해당 연도의 날짜 열만 제공합니다. 기본 입금일은 가장 최근 주일이며, 날짜 열이 없으면 입력이 비활성화됩니다.
3. QR 스캐너로 읽고 Enter를 누르거나, 코드를 입력하고 **QR 조회**를 누릅니다. 사진도 선택할 수 있고, 여러 QR이 있으면 한 개를 선택합니다.
4. 기본적으로 작정금액이 있고 기존 입금이 비어 있으면 자동 기록합니다. 자동 기록을 끄면 금액 확인 후 기록합니다. 작정금액이 없으면 입금액을 직접 입력합니다. 여기서 바꾸는 것은 **선택한 입금일의 금액**입니다.
5. **파일 저장** 또는 `Ctrl+S` / `Cmd+S`로 저장합니다. 기록 후 종료할 때에도 저장합니다. 같은 셀의 기존 금액은 자동 덮어쓰지 않고 변경 확인을 거칩니다.

`.xls`는 Excel에서 `.xlsx`로 변환해야 합니다. 엑셀을 Excel에서 수정한 후에는 앱에서 파일을 다시 열어 주세요. 저장 전 외부 변경을 발견하면 기존 파일에 덮어쓰지 않고 앱에 입력 내용을 유지합니다.

## 프로젝트 구조

| 파일 | 역할 |
| --- | --- |
| `main.py` | 실행 진입점, 선택적인 엑셀 경로 인수, 플랫폼별 아이콘 처리 |
| `UILayout.py` | 단일 화면 UI, QR/금액 입력, 선택기, 입력 내역, 백그라운드 작업 |
| `readxlsx.py` | 머리글 탐색, 전체 행 QR 색인, 조회·금액 검증·저장 |
| `QRParsing.py` | 5개 항목의 QR 형식 검증, 사진 QR 해독 |
| `DateFucntion.py` | 가장 최근 주일 계산 (기존 파일명 유지) |
| `tests/` | QR·연도·저장·보존 및 Tk 콜백 회귀 검사 |

스캐너 코드는 `1-일반`, `2-신학생`, `3-선교사`, `4-개척교회`, `5-북한` 항목과 ID를 조합합니다. 예: `1-7`. 사람 이름으로 행을 추정하지 않으며 QR이 중복되어 있으면 기록을 차단합니다.

## 2026년 기준 파일에서 확인한 문제

- 이전 코드는 `OFF선교헌금 `처럼 시트명 끝 공백까지 고정했지만 기준 파일은 `OFF선교헌금`입니다.
- `2024년 작정금액`이 고정되어 있었고 이름은 G열로 가정했습니다. 기준 파일은 2025/2026년 작정금액 열과 H열 이름을 사용합니다.
- QR 검색 범위가 2,300행으로 제한되어 신규 등록자를 찾지 못했습니다. 현재는 전체 행을 색인합니다.
- JPEG의 신규 QR 두 개는 기존 검색 제한인 2,300행 이후에 있고, 기존 QR 한 개와 함께 정상 해독됩니다.
- 신규 등록자 중 작정금액이 없는 경우와 기존 입금액이 있는 경우가 있어, 기존 금액 보호 및 수동 입력 흐름을 검증했습니다.
- 기준 OFF 시트는 2025년 작정금액이 있지만 입금일 열은 2026년만 있습니다. 없는 연도의 입금일 열을 생성하거나 다른 연도로 대신 기록하지 않습니다.

## 저장과 성능

앱은 openpyxl의 읽기 전용 모드로 값을 읽고 QR·머리글을 색인합니다. QR 조회 시 시트를 다시 순회하지 않습니다. 파일 읽기·사진 해독·저장은 작업 스레드에서 실행하며 Tk 위젯은 메인 스레드에서만 변경합니다.

저장은 전체 통합문서를 openpyxl로 다시 내보내지 않고, XLSX ZIP 내부의 선택한 숫자 셀과 Excel 재계산 설정만 수정합니다. 다른 ZIP 구성 요소의 원래 바이트를 유지하므로 외부 연결·VML·주석·스타일·다른 시트를 보존합니다. Excel에서 열 때 수식을 재계산하도록 설정하며 앱 자체는 수식을 계산하지 않습니다. 수식으로 된 작정금액은 Excel이 마지막으로 저장한 계산값을 사용하므로 Excel에서 먼저 계산·저장해야 합니다. 입금 대상이 수식 셀이면 덮어쓰기를 차단합니다.

저장 전 원본을 같은 폴더의 `.backups/`에 타임스탬프가 있는 파일로 복사합니다. 임시 XLSX 작성·ZIP 검사 후 원본 파일을 교체하며, 실패하면 입력 내용과 원본을 유지합니다. 백업은 자동 삭제하지 않습니다.

## 라이브러리

재현 가능한 설치를 위해 [openpyxl 3.1.5](https://pypi.org/project/openpyxl/3.1.5/), [Pillow 12.3.0](https://pypi.org/project/pillow/12.3.0/), [zxing-cpp 3.1.1](https://pypi.org/project/zxing-cpp/3.1.1/)로 고정했습니다. 기존에 사용하지 않던 `openpyxl_image_loader`와 불필요한 asyncio 의존 코드는 제거했습니다.

현재 macOS 작업 환경의 `.venv`는 Tk가 포함된 Codex 번들 Python 3.12로 구성되어 있습니다. 설정 중 Homebrew의 `python-tk@3.14` 설치가 공용 의존성 업데이트를 동반해 중단했으며, 그 과정에서 ca-certificates, OpenSSL, readline, sqlite, xz, pkgconf, expat, Python 3.14의 일부 버전이 설치되었습니다. 이 앱은 해당 Homebrew 설치에 의존하지 않습니다.

## 검증

```sh
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pip check
```

실제 참고 데이터의 통합 검사는 Git에서 제외한 로컬 전용 `tests/test_local_reference.py`에 있습니다. 해당 파일과 기준 엑셀·JPEG가 있는 작업 환경에서만 실행합니다. 공개 테스트는 생성한 가상 데이터만 사용합니다. 모든 저장 검사는 임시 복사본에서 실행하며 기준 원본은 수정하지 않습니다. GUI 검사는 Tk 또는 화면이 없는 환경에서 건너뜁니다.

기준 파일의 실제 QR 세 개 해독, 신규 행 조회, 선택 셀의 저장 값, 백업 일치, 다른 ZIP 구성 요소 보존을 확인했습니다. Tk 실행·선택 변경·중복 스캔·금액 수정·저장 실패·종료 저장도 검사합니다. macOS 컴퓨터 제어 권한이 없어 화면 캡처를 통한 시각 검증은 수행하지 못했습니다. Windows 빌드 서버에서 생성된 EXE를 직접 실행하여 Tk 초기화·QR 해독·엑셀 저장을 검증했습니다. 사용자 Windows PC의 실제 스캐너 연결과 Excel 앱의 재계산은 별도로 확인해야 합니다.

## Windows 실행파일

Windows x64용 단일 실행파일은 `dist/ReadQRToxlsx.exe`입니다. 실행할 때 Python을 설치할 필요가 없으며, EXE를 더블클릭하고 앱에서 엑셀을 선택합니다. 기준 엑셀과 사진은 EXE에 포함하지 않습니다.

빌드 방법은 [WINDOWS_BUILD.md](WINDOWS_BUILD.md)에 있습니다. 별도 `codex/windows-exe-20261010` 브랜치의 [Windows 빌드 결과](https://github.com/AriSongYe/ReadQRToxlsx/actions/runs/38056717004)에서도 결과물을 받을 수 있습니다. 빌드 당시에는 별도 브랜치의 앱 소스와 빌드 설정만 사용했습니다. 이후 앱 소스·빌드 설정·가상 데이터 테스트·공개용 문서를 `master`에 반영했습니다. 기준 엑셀·JPEG·실제 참고 데이터 통합 검사는 Git에서 제외합니다.
